# 第十八批：项目 ACL 实施与验收

> **已过时：** 本文描述的多用户、登录和项目 ACL 已在 `3cb38d7` 中删除，仅作历史记录。当前是单用户本地模式，权限设计见 README 的「本地访问」和「执行隔离」。

范围：执行已批准方案的第一批。**本报告不代表跨进程协调或自动恢复已经完成。** 所有测试使用工作区外临时数据；没有迁移用户真实数据库、替换全局解释器、调用真实模型或启动真实压测。

## 一、业务及架构保持项

Agent 仍负责 JMeter 测试计划、执行、报告分析及知识积累，没有替换规划器、拆分新 Agent 或改写业务 Prompt。旧项目显式保留 `legacy_shared`（仍需认证和既有全局角色），新普通项目由创建者持有并默认私有。权限为全局角色与项目权限交集；管理员可审计管理成员，但不会因此自动读取私有内容。

核心调用链：认证稳定用户 ID → 当前 DB 授权快照 → API/Tool/模型边界刷新 → 同步数据及路径守卫 → 持久化 → 发布缓存。发送内容前复核当前账号及撤权版本。权限服务不可用时拒绝继续，不当作共享权限。

## 二、逐项修改说明

### 1. 持久项目策略、成员、身份代次及审计

- **【修改内容】** 新增独立策略/成员/审计/用户访问版本表；旧项目策略补齐但不猜测 owner；新项目及私有策略同事务提交。权限预览绑定旧版本、新成员映射及用户身份代次，提交时校验。
- **【修改原因】** 全局角色无法表达项目隔离；用户名或可复用数字 ID 不能独立证明同一个账号。分开提交可能留下无策略的公开项目。
- **【影响范围】** `models/db.py`、`project_access.py`、DBStore、所有项目创建入口。Prompt/Tool 定义不变；授权范围改变实际可读 Context。
- **【风险等级】** 高。存量默认共享是兼容行为，不是全部历史数据私有化。
- **【验证方式】** 临时 SQLite：角色交集、管理员不可自动读、账号停用/重建、并发过期预览、事务失败回滚、新项目策略与数据原子性。
- **【为什么这是最优方案】** 在既有数据库上增加少量表，保留旧业务数据及角色，不引入新身份系统或推测式迁移。

### 2. API、DB、缓存统一资源边界

- **【修改内容】** 服务端解析计划/执行所属项目，列表与统计先授权再分页；缓存返回隔离副本，持久化成功后才发布。禁止覆盖隐藏资源及改换归属。
- **【修改原因】** 前端隐藏按钮不能阻止直接 HTTP/MCP 调用；可变缓存对象会在 DB 失败前泄露未提交修改。
- **【影响范围】** 中间件、业务路由、DBStore、SharedStore、执行生命周期；Tool 读写受到同一权限约束。Memory/Prompt 文本不变。
- **【风险等级】** 高。原来绕过持久化的直接缓存写法需要同步修正。
- **【验证方式】** 真实 ASGI/认证/临时 DB 集成，覆盖 owner、项目只读成员、无关用户、管理员，以及非法关联、分页计数与失败无副作用。
- **【为什么这是最优方案】** 复用现有入口和数据访问层，采用统一守卫，不逐个复制权限规则。

### 3. 文件、报告、来源归属及递归删除

- **【修改内容】** 使用规范化真实路径及全部登记归属的交集校验 JMX、CSV、报告、备份与目录；静态报告检查最终目标；阻止目录回退重新发现隐藏文件。由私有快照或项目目录生成执行时继承源项目，不降为默认共享项目。Windows 大小写别名同时检查全部匹配归属。项目删除在提交前核对每个后代路径。
- **【修改原因】** 注册 ID 校验不能防止路径别名、静态目录穿越、私有快照重新归类及递归删除误伤其他项目登记文件。
- **【影响范围】** `project_scope.py`、文件/数据/JMX 工具、报告解析器、静态文件、执行登记、删除入口。Tool 参数不变，错误路径提前拒绝；Workflow 不启动未授权工作。
- **【风险等级】** 高。无法证明所属项目的孤立文件不再自动可见。
- **【验证方式】** 真实 HTTP 编码点段/反斜杠、实际日志/报告目标检查、私有快照及未登记 JMX 的 owner/只读成员测试、大小写双归属、异项目后代文件删除拒绝且文件/DB 保留。
- **【为什么这是最优方案】** 在已有文件调用之前收紧归属验证，无需移动既有文件或重新生成测试计划。

### 4. 撤权、模型、Tool 与流式发送

- **【修改内容】** 模型调用前后、工具确认后和执行前后刷新权限；每次流发送轻量检查账号及撤权版本。资源索引加载结束也复核权限，防止加载途中撤权后发布旧快照。仅权限变更/删除的固定 JSON 确认信息在新权限范围内发送。
- **【修改原因】** 长请求可能保留撤权前 Context；只在请求开始验证不足。自己转交 owner 或删除项目会使旧范围失效，但操作提交成功不应误报失败。
- **【影响范围】** adapters、ToolRegistry、AuthenticatedStreamingResponse、认证中间件、权限管理响应。Prompt 语义不变；实际模型输入受当前权限过滤。
- **【风险等级】** 高。已发送信息及已开始的外部操作无法撤回；取消不等于远端工作停止。
- **【验证方式】** 模型前撤权不调用 SDK、确认后撤权不执行 Tool、发送前撤权阻断、加载资源期间撤权拒绝、转交及删除响应成功后旧读取仍拒绝。
- **【为什么这是最优方案】** 在实际副作用及交付边界复用守卫；每个片段不重建全部资源索引，也不增加模型请求。

### 5. Memory、Fact/Hypothesis 与 RAG

- **【修改内容】** 会话命名空间绑定用户身份代次、角色及权限版本；不将旧不明范围历史合并到新会话。知识直接读取、搜索、计数和写入均验证来源；来源不明的旧知识不能进入私有项目上下文；拒绝跨项目伪造来源。
- **【修改原因】** 来源校验与用户授权不同；只限制当前报告而继续读取撤权前历史仍会泄露信息。
- **【影响范围】** BaseAgent、RAG Store、Fact/Hypothesis Ledger、分析回执。Context 筛选及 Memory 命名空间改变，原始历史保留，不自动归属或删除。
- **【风险等级】** 高。权限版本变化可能要求新会话，不承诺无缝延续旧上下文。
- **【验证方式】** 来源隐藏/缺失/冲突、直接 ID 访问、搜索前过滤、账号身份变更及撤权后保存拒绝；启动迁移显式内部权限且不泄漏到用户调用。
- **【为什么这是最优方案】** 使用已有来源和稳定身份作为边界，不重写向量库、不迁移归属不明的历史内容。

### 6. 调度、执行收尾、自愈与自动调优

- **【修改内容】** 新调度持久绑定创建者身份；执行时重读活动账号及项目权限。旧无主调度只能操作共享项目。撤权前未启动任务不再运行；已有本进程任务仅可收尾既有状态字段。shutdown 使用有限内部能力释放本进程资源。自愈/AutoTune 在备份、分析、修改及恢复前重验路径写权限。
- **【修改原因】** 后台任务不能借无用户上下文取得系统权限；撤权时全部持久化失败也会遗留永久 pending 状态；未经授权的备份恢复同样是写操作。
- **【影响范围】** Scheduler、ExecutionLifecycle、SelfHeal/AutoTune、回执清理。Workflow 目标不变；失权后停止后续步骤，已知结果可有限落库。
- **【风险等级】** 高。撤权后可能保留未恢复备份，需要重新获得授权后核实；不能自动覆盖文件。
- **【验证方式】** 调度创建者停用/删除/身份代次改变、启动前撤权、持有者/非持有者收尾、shutdown 无用户范围、AutoTune 撤权恢复拒绝及取消传播。
- **【为什么这是最优方案】** 明确区分新副作用与既有任务收尾，不给整个后台生命周期管理员权限，也不丢弃真实终态。

### 7. WebSocket、通知及回执

- **【修改内容】** 每个订阅者按自己的 Token/身份验证执行归属，发送前复核，恢复生产者上下文；私有项目不走全局 webhook。分析回执查询、重放、检查点及完成验证稳定身份和执行权限。
- **【修改原因】** 不能使用消息生产者的授权替订阅者授权；全局通知接收者也不等于私有项目成员。
- **【影响范围】** WS Manager、Notifications、AnalysisReceipts；不改变消息业务语义，拒绝未经授权的投递。
- **【风险等级】** 高。跨 worker 路由仍未实现；本批不得据此开启多 worker。
- **【验证方式】** 多身份订阅、撤权/失效账号、隐藏执行、Tokenless 拒绝、回执重放隔离与元数据清理测试。
- **【为什么这是最优方案】** 保留当前传输协议和回执去重，在发送端补齐接收者授权，不引入新的消息基础设施。

### 8. 前端权限管理与可维护性

- **【修改内容】** 项目设置增加权限信息、成员 ID/角色输入、影响资源预览及确认提交；无 read 权限的管理员管理页面不预取私有内容。服务端继续独立校验。
- **【修改原因】** 旧项目转私有需要显式 owner/成员映射，不能无提示转换；界面必须准确表达管理权与读取权的区别。
- **【影响范围】** Vue 项目设置、API 类型及方法；不改变 Agent Prompt、Tool Schema、Memory、执行流程。
- **【风险等级】** 中。成员以稳定 ID 管理，不新增全局用户目录暴露。
- **【验证方式】** 前端 8 个测试文件、104 个测试通过；vue-tsc 通过；Vite 构建通过，产物写入工作区外。
- **【为什么这是最优方案】** 在现有设置页增加必要交互，避免单独引入管理应用或只依赖前端鉴权。

## 三、性能与 Token

7 个关键 Prompt 定义 AST 对比保持一致；本批不增加模型调用、推理步骤或 Token 预算。授权可能减少进入模型的不可访问内容，未做真实模型性能测量，不虚报节省比例。

普通模型/工具边界仍加载当前授权及资源索引；流片段改为当前账号与权限版本轻量复核，避免每片段扫描全部计划和执行。完整资源索引仍有规模成本，跨进程批次将处理 DB 权威快照和缓存一致性，不能提前声称性能问题全部解决。

## 四、兼容与部署限制

1. 启动不再把未知孤立文件自动扫进默认项目。已有 DB 登记照常恢复；孤立文件留在磁盘，需显式核对归属后登记，不删除或猜测私有 owner。
2. 单 worker ACL 已接入；Session、容量、调度领取、取消 owner、确认、MCP/WS 路由、RAG 写协调还需下一批，不可只改 workers 数量上线。
3. 隔离测试运行时是 SQLite 3.53.4。全局 `D:/python/python.exe` 自带 SQLite 未被替换；多连接 WAL 风险及运行时升级前置要求见已批准方案。
4. 当前账号有权访问的内容仍是模型不可信输入；ACL 不等于消除 Prompt Injection 或保证模型正确。
5. ACL 启用后不能回退到不懂 ACL 的旧版本绕过权限；生产迁移、部署备份与运行时替换需要独立操作窗口。
