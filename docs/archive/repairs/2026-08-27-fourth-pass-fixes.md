## 1. RAG API 的组合过滤、空结果和分页

【修改内容】文档列表在关键词查询时同时保留 module/doc_type；搜索无结果时不再发起丢失过滤条件的全局回退。列表直接传递 limit，修复要求100条却先被默认50条截断的问题；两个API拒绝零或负数limit。

【修改原因】底层查询修正后，路由仍可能绕开过滤；不相关模块的结果会进入展示和人工检索上下文，空结果也产生重复查询。

【影响范围】RAG路由、现有列表/搜索消费者。Prompt和Tool schema不变；Memory/Context检索范围更准确，Workflow不新增步骤。当前仍是共享工作区权限模型，模块过滤不是项目级ACL。

【风险等级】中。原来无结果时返回的其他模块内容现在消失，这是恢复请求过滤语义；total仍表示本次返回条数，不冒充数据库总数。

【验证方式】组合条件、空结果、limit转发、ASGI非正数422；真实临时LanceDB冷启动经API工作线程查询，验证其他模块/类型不会混入。

【为什么这是最优方案】复用hybrid_search，修复丢失的参数，不改知识库结构或另建搜索实现；没有结果即返回空列表，避免无意义的第二次查询。

## 2. 查询/采样不阻塞事件循环，避免过期缓存回写

【修改内容】RAG列表/搜索和系统资源采样进入工作线程。向量查询不再将结果回写ID缓存，防止延迟查询把已删除或已更新的记录覆盖回来。资源采样回退使用配置中的CPU/内存阈值，与正常路径的包含边界比较保持一致。

【修改原因】同步embedding/数据库操作与阻塞式CPU采样会暂停同一事件循环的其他请求；查询异步化若照旧写缓存，会新增查询与删除竞态。原回退硬编码80/85，可能把超过用户配置阈值的机器显示为健康。

【影响范围】RAG路由/store、系统资源API。Prompt/Tool/Memory格式不变；Context不再因延迟查询缓存而读到重新出现的已删除记录。Workflow仍使用原执行准入机制，本批没有放宽资源门槛。

【风险等级】中。工作线程中的读取不会被客户端取消强制终止；其他RAG写入/统计/元数据路径仍有同步工作，没有宣称全链路无阻塞或线程池具有统一背压。并发查询可返回其查询时的快照，但不能将快照重新写成当前缓存。

【验证方式】线程ID断言、真实LanceDB工作线程查询、查询取得结果后发生删除的交错测试、采样失败后的配置阈值回归。

【为什么这是最优方案】仅迁移已确认的阻塞入口，去掉不必要的查询缓存写入；不把同步写操作简单搬进线程后引入新的写竞争，也不重建整个存储层。

## 3. Memory 压缩只移除实际提交摘要的消息

【修改内容】一次压缩选取最多15条旧消息的前缀，并避开Tool调用组中间的切分点；仅删除这批消息，保留未提交摘要的历史以及摘要等待期间的新消息。加入前缀身份校验，窗口已变更时不覆盖它。摘要输入保留Tool调用ID/名称并标记截断内容；空白摘要不再清除历史。

【修改原因】旧实现仅向模型发送old_msgs[-15:]，却删除全部old_msgs；摘要完成时重新计算保留窗口，还会误删等待期间产生的新消息前面的历史。这是实际信息丢失，不是正常的有损摘要。

【影响范围】ConversationMemory的短期窗口、滚动摘要、持久化dirty标记与Agent Context。Tool wire格式和Workflow不变；摘要Prompt的目标与安全语义保留，仅补充必要的消息来源标识。

【风险等级】中。保留之前被误删的消息会增加部分后续上下文长度，这是恢复正确性，不宣传Token必然下降。摘要内容仍有损、单条内容仍受长度限制；模型摘要质量、长期保留策略未完成评测。

【验证方式】40条消息场景验证每条均出现在摘要输入或保留窗口；摘要等待时追加消息、空白摘要、既有滚动摘要/持久化/原生消息回归。

【为什么这是最优方案】明确“发送哪些、删除哪些”的边界，复用现有摘要与窗口，不增加额外摘要调用、不把遗漏内容伪装成已压缩知识。

## 4. 规划和检查点的结构化输出解析

【修改内容】规划JSON改用JSONDecoder定位完整对象，正确处理字符串中的花括号和转义。验证steps数组、每项对象、非空说明、正整数且唯一的step_id、Tool参数对象和字符串字段。检查点同样使用完整JSON与规划校验，只接受布尔true，并补入现有安全系统提示。

【修改原因】手数花括号和非嵌套正则会误截断有效参数；null、字符串steps、重复ID可能触发异常或进入不可靠计划。检查点原先缺少共同安全规则，且无法解析正常的嵌套new_steps。

【影响范围】TaskPlanner、BaseAgent检查点与后续Tool选择。Memory schema不变；Context获得完整的工具参数。无效计划继续采用现有有限格式重试/直接ReAct回退，不新增工作流；检查点仍默认关闭。

【风险等级】中。过去被容忍的空说明、重复ID或错误类型现在明确拒绝；不自动猜测或修正有风险的Tool参数。

【验证方式】转义/不配对花括号、7种非法steps结构、检查点嵌套计划及安全提示；加强后的两个测试还在原始快照方法上复现失败，未回写或回滚当前源码。

【为什么这是最优方案】沿用标准JSON解析器和已有PlanStep契约，只修结构边界；不引入新规划器，不依赖新增Prompt让错误类型碰巧消失。

## 5. 最终请求的上下文预算

【修改内容】纯推理步骤先追加当前指令，再检查预算；文本Tool Calling回退在加入工具说明后，按最终文本形式估算Token并预留输出/安全余量。选择消息时保留原生调用组，转换后不会留下孤立工具结果。策略/当前任务/工具交换无法容纳时，在模型请求前明确失败。

【修改原因】先截断后追加长指令、或在预算计算之后追加文本工具说明，均可能突破已计算的窗口；先转换tool role再截断还可能拆散调用与结果。

【影响范围】BaseAIAdapter、BaseAgent推理/回退调用；原生工具路径保留既有计算。Prompt语义、工具清单、Memory持久格式和Workflow步骤不变，只修实际发送内容的预算边界。

【风险等级】中。超大输入现在明确拒绝，不能靠删掉当前任务或安全规则继续执行。仍使用字符分布估算，不是真实模型tokenizer；规划/总结等其他请求的统一窗口预算仍需后续核验。

【验证方式】最终文本Token估算不超预算、完整Tool组淘汰、当前任务保留、超大schema不发模型请求、追加长步骤后的拒绝；原始快照回归证明旧行为会失败。

【为什么这是最优方案】复用现有消息分组和预算函数，不裁掉工具清单、不改原生协议、不根据未经评估的工具选择规则牺牲任务能力。

## 6. OpenAPI/Swagger 的结构与引用展开边界

【修改内容】JSON/YAML解析和规范解析进入工作线程；输入树限制深度64、遍历节点50000、文本总UTF-8字节5MiB，拒绝循环别名、非有限数值及不支持的非JSON值。整个规范共用引用展开节点预算，并限制展开深度。info/paths/components/server、认证类型、参数项等结构异常返回明确失败。

【修改原因】正文长度限制不能阻止短文档的循环/重复引用展开；局部字段类型错误仍可能抛未处理AttributeError。同步解析较大文档也会占用事件循环。

【影响范围】URL与内联OpenAPI导入、计划生成前的校验。Prompt/Memory/Context不新增数据；Tool/Workflow收到失败后不进入该次生成与执行。原有普通本地$ref、Swagger和HTTP认证解析继续保留。

【风险等级】中。超出预算的复杂规范需拆分或显式设计更大预算，不能声称支持全部OpenAPI语义。预算检查发生在解码之后，不是JSON/YAML解析器或HTTP压缩解码的完整内存沙箱；初始URL授权、DNS重绑定、代理、报告同源风险仍未解决。

【验证方式】循环别名、70层嵌套、超限文本、二叉重复引用展开、顶层及嵌套非法结构；原有URL跳转/下载超时、真实SDK模拟、导入登记和执行失败契约仍在全量回归内。

【为什么这是最优方案】在生成前增加有限的确定性校验，保留受支持的规范功能；不把异常转成空成功，也不抓取外部$ref或自动运行不明测试目标。
