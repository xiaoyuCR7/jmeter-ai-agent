## 变更记录

### 1. 身份、角色与刷新令牌

【修改内容】统一 REST、报告静态文件、WebSocket 与 MCP 的身份边界；修复令牌 ORM 契约、刷新轮换、退出撤销和实时角色校验。浏览器使用 HttpOnly/SameSite Cookie；配置写入限管理员，业务写入限操作员。

【修改原因】旧令牌存储字段不匹配，业务面缺少一致的服务端授权；退出不能只清理浏览器状态。

【影响范围】auth、DBStore、路由、中间件、前端登录/API；Prompt/Memory 内容不改，Tool/Workflow 在认证后执行，Context 增加调用人。

【风险等级】中：旧访问令牌需要重新登录；反向代理需正确配置主机与来源。

【验证方式】临时 SQLite + ASGI 回归覆盖角色变化、停用、并发轮换、旧令牌退出；Axios 假适配器覆盖刷新及退出竞态。

【为什么这是最优方案】复用已有用户和令牌表，不引入外部身份系统；授权在服务器执行。

### 2. 危险工具确认与参数校验

【修改内容】Registry 编译并执行 JSON Schema；拒绝未声明参数；危险调用冻结参数后等待所属用户一次性批准，拒绝/超时/取消不调用处理器。前端增加待确认面板。

【修改原因】模型自报 confirmed 无法形成权限边界；隐含参数可绕过资源检查。

【影响范围】ToolRegistry、执行/文件工具、确认服务与 UI；Prompt 语义不变，Tool/Workflow 增加真实批准等待，Memory 只保存实际结果。

【风险等级】中：危险工具不再无人确认直接执行；确认状态仅在当前服务进程内有效。

【验证方式】参数类型、额外参数、跨用户确认、确认重放、参数后改、超时和未登录测试。

【为什么这是最优方案】所有 Agent/MCP 调用复用唯一工具边界，避免在每个 Prompt 中重复实现安全逻辑。

### 3. 原生工具消息与上下文预算

【修改内容】保留 assistant tool_calls、tool_call_id 与结构化结果；适配 OpenAI/Anthropic；消息截断按完整调用批次，固定本轮任务与步骤；工具观察保留关键 ID/状态并限长。

【修改原因】丢失调用关联、双重 JSON 编码和截断半组消息会造成无效请求与上下文污染。

【影响范围】消息模型、适配器、ReAct、短期 Memory、Context；不改变工具职责或业务步骤。

【风险等级】中：文本回退模型与真实供应商仍需端到端验收；预算仍为估算，未声称实际 token 节省百分比。

【验证方式】供应商 SDK 假响应、Memory JSON/SQLite 往返、调用批次截断和取消补齐。

【为什么这是最优方案】沿用原有适配器，只补齐协议所需信息和最小预算约束。

### 4. 会话归属与并发

【修改内容】短期会话键绑定用户、Agent 类型和客户端会话 ID；同一会话重叠运行快速失败；Agent 子类共用并发限制。

【修改原因】不同用户同名会话可串用历史，同一会话并发覆盖状态，子类限制并非全局限制。

【影响范围】BaseAgent/ConversationMemory/Context；Tool/Prompt 语义不改，Workflow 在冲突时给出明确失败。

【风险等级】中：旧无归属会话不会自动归属到新用户；保留旧数据而不擅自迁移。

【验证方式】不同用户隔离、同会话重叠、子类共享 Semaphore、取消后清理回归。

【为什么这是最优方案】在入口绑定已认证身份，无需重写 Session 或增加分布式锁。

### 5. MCP SSE 协议

【修改内容】实现声明的 2024-11-05 旧式 SSE：每连接独立 endpoint/session，POST 返回 202，响应经所属 SSE 通道；初始化状态、JSON-RPC、取消、队列和会话配额；参数错误 -32602，业务错误 isError。

【修改原因】全局广播和 POST 直返响应不符合原声明协议，也可能串会话。

【影响范围】MCP Server/routes/配置 UI，复用同一 Registry/身份/确认；Memory/Prompt 不直接修改。

【风险等级】中：不支持新 Streamable HTTP；多 worker 需要粘性路由或外置会话存储。

【验证方式】41 项传输/生命周期回归与前端模拟握手；真实 IDE/MCP SDK 尚未验证。

【为什么这是最优方案】修复现有声明版本，避免同时迁移协议与替换框架。依据 [MCP transports](https://modelcontextprotocol.io/specification/2024-11-05/basic/transports) 与 [工具错误契约](https://modelcontextprotocol.io/specification/2024-11-05/server/tools#error-handling)。

### 6. 流式清理、退出失效与 Host 边界

【修改内容】SSE 发送异常/断连关闭源生成器，WS/SSE 发送前核验令牌；Agent 取消并等待后台运行；Host 显式名单先于 Origin 推导，覆盖 IPv6 与 WS 拒绝帧；修复前端 1006 非法主动关闭码与卸载重连。

【修改原因】断流后任务可能仍运行，退出后长连接仍可收数据，伪造 Host 可影响同源判断。

【影响范围】ASGI、SSE/WS、BaseAgent、前端 composable；Workflow 生命周期改变，Prompt/Memory 内容不改。

【风险等级】中：自定义部署域名须加入 ALLOWED_HOSTS，不能使用通配符。

【验证方式】真实 ASGI send 失败、退出后无后续数据、WS close1008、Host/Origin/IPv6、前端定时器回归。

【为什么这是最优方案】在已有传输边界关闭资源，避免重复实现所有路由的清理。

### 7. 编辑器往返保真

【修改内容】基于原树逐字段补丁，保留未知节点、插件、脚本、断言、禁用标志和多线程组；不支持的复杂编辑明确阻止保存；JMX 编辑器先保存再运行；数值表达式不自动夹紧，显式启用调度后可设置时长。

【修改原因】重建简化树会静默丢失负载和断言；控件挂载可改变原始值。

【影响范围】TestCaseEditor/JmxEditor/HeadersEditor；不影响 Prompt/Tool/Memory，影响编辑保存到执行的 Workflow。

【风险等级】中：复杂设置需转 JMX 编辑器；未增加新的测试产品逻辑。

【验证方式】无编辑往返、定点修改、未知数据、真实 ElementPlus 输入/开关；独立规格复核 50 测试通过、vue-tsc 通过。

【为什么这是最优方案】修复数据丢失而不重新实现全量 JMeter GUI。

### 8. 统一计划和执行生命周期

【修改内容】Web、Agent/MCP、调度、自愈、调优复用服务；DB 成功后发布缓存；生成/克隆/导入登记计划；每次执行复制原始 JMX 字节并记录 SHA256、原资源目录，统一取消和关闭；报告状态与进程状态分离。

【修改原因】入口各自创建记录、推断完成和启动进程，导致记录缺失、假完成及取消不一致。

【影响范围】routes/tools/调度/专用 Agent/DB/storage；Tool 返回统一 ID，Workflow 以实际状态推进，Memory 可关联执行来源，Prompt 职责不变。

【风险等级】中：旧库新增可空字段，旧数据不凭空补造成功；无进程隔离保证。

【验证方式】临时 SQLite、注入执行器、DB 失败、取消排队、进程/报告分离、迁移两次、恢复环境及错误；生命周期专项 71 通过。

【为什么这是最优方案】集中已有副作用入口，保留 API 字段和业务流程，不增加消息总线。

### 9. 进程所有权与完成判断

【修改内容】持有真实 Popen/PID，Windows 直接 Java 启动而非 shell 拼接；本地/分布式统一等待退出码和并发守卫；取消等待进程树清理，失败保留所有权；执行 ID/远程地址先校验。

【修改原因】脱离启动器、日志稳定推断及 PID 搜索容易假完成、误杀或留孤儿。

【影响范围】executor/distributed executor/lifecycle；Tool/Workflow 取消闭环，Prompt/Memory 不直接改变。

【风险等级】中至高：平台启动选项兼容性需复核；进程树跟踪不等于 OS 沙箱。

【验证方式】36 项执行器模拟回归；未进行真实负载或远程引擎验证。

【为什么这是最优方案】消除 shell 解释及未持有子进程的根因，保留 JMeter 脚本能力；完整隔离仍需受限运行环境。

### 10. 统计与 SLA

【修改内容】CSV/XML 总时长包含最后响应结束；乱序样本分桶、尾桶吞吐修正；未知 SLA 操作符和 NaN/Infinity 均判失败。

【修改原因】错误分母会扭曲容量结论，未知条件和非有限数不能误报通过。

【影响范围】ReportParser/SLA/Fact/报告与分析输入；Prompt/Tool 定义不改，Memory 得到修正指标，Workflow 判定更可靠。

【风险等级】低至中：历史报告重新计算后吞吐数值可能变化，这是错误修正。

【验证方式】新增 14 项 CSV/XML/SLA 失败回归转绿，关联 50 项通过。

【为什么这是最优方案】修正计算口径，不调整用户配置的 SLA 阈值。

### 11. 文件边界

【修改内容】通用 safe_path 不再允许整个后端目录；文件工具动态读取配置、realpath+commonpath 校验；报告/备份只读，写入限定计划和测试数据；JMX 更新不允许改执行快照。

【修改原因】相似前缀和符号链接检查不足，配置可被读取，执行证据可被工具覆盖。

【影响范围】config/file/JMX 工具；Tool 权限收紧，Prompt/Memory 不改；Workflow 保留显式编辑入口。

【风险等级】中：不再允许把任意后端文件当测试数据；同进程恶意脚本仍需要 OS 隔离。

【验证方式】配置越界、模拟 OS 符号链接解析、报告写删拒绝及合法计划写入；工具权限 12 通过。

【为什么这是最优方案】在现有路径函数处限定边界，不删除合法读报告能力。

### 12. 长期存储一致性

【修改内容】Lance 单次 merge 更新；磁盘成功后更新缓存；失败抛错；读取返回副本；JSON 降级以 fsync+原子替换落盘，并在 Lance 恢复时保留冲突记录后迁移。

【修改原因】先删后写可丢旧数据，cache-only 降级重启即丢，读取到可变对象能绕过持久化。

【影响范围】RAG Store/归档/Memory；Prompt/Tool 语义不改，Workflow 不再把未落盘内容当成功。

【风险等级】中：真实磁盘失败现在显式可见；JSON 降级面向单服务进程，不声称多进程事务保证。

【验证方式】6 个失败回归转绿；当前 RAG 23 项通过，来源隔离与恢复边界仍在补测。

【为什么这是最优方案】复用 [Lance merge 更新](https://docs.lancedb.com/tables/update)，保留已有存储后端而不增加新数据库。

### 13. 执行证据与记忆来源

【修改内容】执行持久化 context_snapshot（项目、计划、环境及配置指纹）；FactSheet 保存并核对 JTL SHA256；同一执行不接受其他报告路径；RAG 按可信来源生成稳定 ID 和 context_scope。

【修改原因】仅凭模块名、版本名或模型提供的执行 ID 会混用不同环境证据；报告被改后旧事实不能继续充当真值。

【影响范围】Execution/DB/Fact/Analysis/RAG 同步；Memory 与 Context 增加来源约束；Tool/Workflow 使用登记的执行，Prompt 事实内容不虚构归属。

【风险等级】中：没有来源快照的旧记录保留，但不自动归入当前环境的历史证据。

【验证方式】环境快照往返、报告篡改拒绝、跨来源 ID 去重、冷启动 scope 查询、JTL 越界与登记路径错配回归。

【为什么这是最优方案】复用现有执行记录和哈希，不迁走数据或让模型推断旧记录归属。

### 14. 假设验证与手工知识标记

### 16. 统计窗口、SLA、漂移和异常 JSON

【修改内容】吞吐窗口包含响应结束时间，分桶以实际时间归一；未知 SLA 运算符和非有限值失败；漂移按真实日期回归，保留零值，证据不足为 unknown；无穷异常边界输出 null。

【风险等级】中：旧报告重算数值可能改变，这是统计修正，不应与旧错误口径直接比较。

【验证方式】CSV/XML、乱序、100ms短窗口、尾桶、SLA未知/NaN、非每日趋势、错误率零值、无证据和严格 JSON 序列化回归。

【为什么这是最优方案】修正确定的数学和序列化错误，保留现有指标与阈值，未引入新统计库。

【影响范围】ScheduleRunner/共享执行服务；Prompt/Memory/Context 不变；Tool/Workflow 执行记录与取消保持一致。

【风险等级】中：按单服务进程工作，未实现多 worker 分布式租约或 DST 验收。

【验证方式】星期/range/step/非法表达式、DOM/DOW、下一时刻、并发与取消回归。

【为什么这是最优方案】修正现有调度器，不引入额外任务队列或调度基础设施。

### 19. HTTP、OpenAPI 和 CI 闭环

【修改内容】补齐本地分析接口，修复基线/CSV/漂移前后端契约；OpenAPI 支持明确子集并注册 DB/计划/执行；execute 仅接受 JSON boolean；CI 使用真实执行终态、非空 JTL 和 SLA 判定退出码。

【修改原因】可点击功能请求不匹配；导入失败、警告和执行开关可能被假装成功；CI 不能可靠阻断失败。

【影响范围】routes/analysis_routes/OpenAPI/前端 API/CI；Tool 描述同步能力边界；Prompt/Memory 不新增步骤；Workflow 与 Context 使用真实执行 ID。

【风险等级】中：不支持的 OpenAPI 语义明确报错；Prometheus 远程关联返回 501；CI 需配置已审核计划 ID 和令牌。

【验证方式】ASGI/前端请求契约、本地引用/循环引用/参数/body/bearer/Swagger、false 字符串拒绝、CI 缺ID/HTTP错误/超时取消/SLA失败非零退出；无真实 CI 平台运行。

【为什么这是最优方案】复用正式 REST 与执行生命周期，删除示例里的虚假成功路径，不用 LLM 文本代替验收。

### 20. 工具批次、超时与总上下文预算

【修改内容】单响应工具调用数默认上限8；上下文预算纳入 schema、2000输出预留与256余量，消息部分仍不超过原上限；危险工具超时停止自动重试；文本工具 fallback 用 JSONDecoder 保留嵌套参数。

【修改原因】无界批次可在一轮产生大量副作用；原预算漏算工具定义；超时写入结果未知，重试可能重复执行；正则不能正确解析嵌套 JSON。

【影响范围】BaseAgent/adapters/config/Tool/Memory；Prompt 同步重试规则；Context 原生消息关联保留；Workflow 超限显式失败。

【风险等级】中：默认总预算16384须按实际模型容量调整；估算不等于供应商 tokenizer，全部40工具仍保留。

【验证方式】9调用批次无副作用、危险超时不重试、预算不足不发请求、嵌套单/多工具 JSON 和 Agent 全套回归。

【为什么这是最优方案】先控制确定的失控边界，不凭关键词删工具，也不对未知副作用做无条件重试。

### 21. 分析 Prompt 与输入截取

【修改内容】保留报告 JSON 字段和分析职责，取消强制编造容量/根因/参数的示例；明确数据不可信、缺项为未知；时间段覆盖尾部和极值，错误示例限长并标明抽样。

### 22. AutoTune 和 SelfHeal 验收

【修改内容】AutoTune 无合格候选/无有效样本/非有限指标/恢复失败均失败，正确处理四种比较运算；SelfHeal 只应用有响应证据的简单提取修复，区分 applied/verified，重跑未通过不报修复成功。

【为什么这是最优方案】保留原搜索与修复算法，只修执行验收和证据边界，不增加新的自动调参策略。

### 23. 文件、资源工具与事件循环
